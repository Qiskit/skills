## Summary

M3 (Matrix-free Measurement Mitigation) provides scalable readout error mitigation for sampling outputs. Standard readout error mitigation inverts the 2ⁿ × 2ⁿ assignment matrix explicitly, which is computationally infeasible beyond about 10–15 qubits. M3 avoids explicit matrix construction by working only with the subspace of bitstrings that actually appear in the measurement results. It uses a local noise model approximation and solves the resulting reduced linear system—via direct LU factorization or a preconditioned iterative method, selected automatically—to compute a quasi-probability distribution over bitstrings that corrects for readout errors. This approach scales to 80+ qubits. M3 is an external package (`mthree`) and is not built into Qiskit Runtime.

## When to use

- Sampling-based experiments (via SamplerV2, direct backend execution, or any source of raw counts) where readout errors affect the measured bitstring distribution.
- Large qubit count circuits (10+ qubits) where the full assignment matrix cannot be constructed or inverted explicitly.
- Experiments that require quasi-probability distributions over bitstrings corrected for measurement errors.
- Noisy simulators with a readout error model (M3 calibrates and mitigates on simulators).

## When not to use

- EstimatorV2. Readout error mitigation for expectation value estimation is handled by TREX, which is built into Qiskit Runtime. M3 is not applicable in this context.
- Noise-free simulators with no readout error model.
- Very small qubit count where simpler matrix inversion approaches are sufficient and require less setup.

## Trade-offs

| Dimension | Value |
|---|---|
| Shot overhead | Low; calibration circuits only (no additional main-circuit executions) |
| Circuit execution count | 1× main + calibration circuits |
| Estimate bias | Reduces readout-error-induced bias in bitstring distributions |
| Learning phase | Yes (single-qubit calibration matrices; scalable to 80+ qubits) |
| Scales with circuit depth | No; overhead is readout-calibration only, independent of circuit depth |

## Configuration

M3 is an external package. Install separately:

```bash
pip install mthree
```

Basic usage pattern:

```python
# Checked against qiskit-ibm-runtime 0.50.0 and mthree 3.0.0.
import mthree
from qiskit_ibm_runtime.executor_sampler import Sampler  # client-side Sampler (>= 0.50.0)

# Map classical bits to the physical qubits they measure
mapping = mthree.utils.final_measurement_mapping(isa_circuit)

# Calibrate M3 for those qubits (runs calibration circuits on the backend)
mit = mthree.M3Mitigation(backend)
mit.cals_from_system(mapping)

# Run the main circuit with the Sampler and collect raw counts.
# backend.run() is no longer supported on IBM backends.
raw_counts = Sampler(mode=backend).run([isa_circuit], shots=4000).result()[0].data.meas.get_counts()

# Apply mitigation; returns a QuasiDistribution
quasi_dist = mit.apply_correction(raw_counts, mapping)
```

`data.meas` assumes the classical register is named `meas`, as `measure_all()` creates; use the circuit's own register name otherwise. M3 only reweights bitstrings that were actually sampled, so post-processing that picks the best bitstring from the sampled set is unchanged by it.

Full documentation and advanced options are at [qiskit.github.io/qiskit-addon-mthree](https://qiskit.github.io/qiskit-addon-mthree/).

## Composability

M3 is applied as post-processing to raw counts after circuit execution completes (hardware or noisy simulator). It is compatible with dynamical decoupling and Pauli twirling (both applied during circuit execution, before M3 post-processing). For readout error mitigation with Estimator, use TREX instead.
